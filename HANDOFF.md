## 1. What QuikLab is

- Free image and PDF tools that run entirely in the browser. Live at
  https://quiklab.online (Vercel).
- Core promise: files never leave the user's device. No upload, no server
  processing, no API routes that touch user files. Every feature must keep
  this true. EXIF/GPS stripping on JPEG re-encode is a deliberate, visible
  privacy feature.
- Two tools today:
  - Image compressor: JPG/PNG/WebP/SVG/GIF. Quality slider or target file
    size (binary search), resize, format convert, PNG8 median-cut
    quantization, a hand-rolled GIF89a decoder plus gif.js encoder for
    animated GIFs, per-image quality override, ZIP download.
  - PDF toolkit (8 tools): merge, split and extract, compress, rotate,
    watermark, image to PDF, PDF to image, and "Add text & links" (places
    text and real clickable hyperlink annotations, built with pdf-lib's
    low-level API because pdf-lib has no link helper).
- Owner: Rupesh (GitHub `RupeshNB-max`, repo `Rupesh02-cpu/quiklab`, public).

## 3. Stack and architecture

- Next.js 16.3.5 (App Router, Turbopack), React 19, TypeScript, Tailwind v4
  installed but the app styles live in one plain CSS file.
- Next 16 has breaking changes vs. older training data. Check
  `node_modules/next/dist/docs/` before relying on memory for Next APIs.
- Everything is client-side (`"use client"` components, Canvas API, pdf-lib,
  pdfjs-dist). Both routes are statically prerendered.
- Key files:
  - `src/app/layout.tsx`: fonts (Inter for UI, IBM Plex Mono only for numeric
    readouts), pre-paint theme script, GA4 + AdSense + Clarity scripts,
    `UnifiedResetProvider`, `SiteHeader`, `ToastProvider`.
  - `src/app/page.tsx` (`/`) and `src/app/pdf/page.tsx` (`/pdf`): metadata,
    JSON-LD, render the app plus About/FAQ sections.
  - `src/app/quiklab.css`: the single stylesheet. Design tokens on `:root`
    with dark theme via `prefers-color-scheme` and `[data-theme]`. All motion
    lives here too.
  - `src/hooks/useImageCompressor.ts`, `src/hooks/usePdfToolkit.ts`: all
    state and logic for each tool. Both use a 3-step wizard
    (Upload, Configure, Result) with `stepIndex`, `maxReachedIndex`,
    `goToStep`, and generation-counter refs (`clearGeneration`,
    `resetGeneration`) that drop stale async results when the user navigates
    or resets mid-operation. These guards were hardened and tested against
    aggressive back/forward clicking. Do not remove them.
  - `src/lib/*`: pure processing (imageProcessing, gifDecoder, gifEncode,
    pdfProcessing, pdfEditor, pdfTypes, format, saveFile).
  - `src/components/Stepper.tsx`: shared step indicator, supports `locked`
    (disabled while a run is in flight).
  - `src/components/AmbientBackground.tsx`, `PageTransition.tsx`: ambient
    idle motion and View Transitions between routes.
  - `src/components/UnifiedUpload/*`: new unified entry point (see section 6,
    not yet deployed).
- `next.config.ts` aliases pdfjs-dist's optional Node `canvas` dependency to
  an empty module (both Turbopack and webpack). `public/pdf.worker.min.js` is
  a copy of `node_modules/pdfjs-dist/build/pdf.worker.min.js`; re-copy it if
  pdfjs-dist is upgraded.

## 4. Design system (the owner cares a lot about this)

- Palette: "darkroom" theme. Accent is safelight red (`--accent` #C8331F
  light, #E4432B dark). Success green `--good`. Neutral grays. The owner
  explicitly said to keep these colors; do not introduce a new palette.
  Adding a needed token (for example an amber "degraded" color) is fine but
  mention it.
- Type: Inter for all UI text and headings. IBM Plex Mono only for real data
  (file sizes, percentages, counts). Fraunces was removed. No monospace UI.
- Feel: Apple-grade polish, generous spacing, one unified workspace column
  (no card-in-a-box, no left/right split), step-by-step flows, alive but
  not neon. The owner dislikes anything that looks "AI generated" or like
  Claude's own UI.
- Motion conventions: spring arrival curve `cubic-bezier(.34,1.56,.64,1)`,
  settle curve `cubic-bezier(.21,.8,.36,1)`, reuse existing keyframes
  (`wizard-step-in`, `stepper-pulse`, `tool-card-in`, `toast-in`,
  `icon-check-draw`), and every animation has a
  `@media (prefers-reduced-motion: reduce)` fallback (about 27 blocks exist;
  match that pattern). Pure CSS/SVG, no animation library, by choice.
- Copy: privacy line is "never leave your device" everywhere. Avoid em
  dashes in new user-facing copy and code comments; the owner reads them as
  an AI tell.
- Layout sizing is dynamic: `SiteHeader` measures itself into `--header-h`
  via ResizeObserver. No hardcoded viewport math.

## 5. Deploy procedure (proven, use exactly this)

1. On `nextjs-migration`: `npx tsc --noEmit` and `npm run build` must be
   clean. Test real flows (see verification below).
2. Commit on `nextjs-migration`, push it.
3. Merge into `main` via a temporary worktree so the working tree is never
   disturbed:
   ```
   git worktree add ../quiklab-main-merge main
   cd ../quiklab-main-merge
   git merge nextjs-migration --no-ff -m "..."
   npm install && npm run build      # next-env.d.ts is generated here; a
                                     # tsc error about LayoutProps in a fresh
                                     # worktree before building is expected
   git push origin main
   cd ../Quiklab && git worktree remove ../quiklab-main-merge --force
   ```
4. Vercel builds automatically. Confirm with the Vercel API (token is
   `VERCEL_TOKEN` in `.env.local`):
   ```
   GET https://api.vercel.com/v6/deployments?projectId=prj_NGYOIv7wyBN82FbUvAhbWmtIkxdZ&teamId=team_TtG3rQS3mDRwxoS4Vm1vcQBN&target=production&limit=1
   ```
   Check `meta.githubCommitSha` matches the merge commit and
   `readyState == READY`, `readySubstate == PROMOTED`.
5. `curl` https://quiklab.online/ and /pdf for 200 plus a content marker from
   the change (cache-bust with `?x=$(date +%s)`).

Past deploy incident worth knowing: after the first Next.js deploy the site
returned a Vercel-level 404 everywhere. DNS was a red herring. The real cause
was the Vercel project's Framework Preset still being `null` from the static
site era. It was fixed by PATCHing the project to `framework: "nextjs"` and
redeploying. If a deploy is READY but serves 404, check that first. Also
test `https://quiklab.vercel.app` to separate DNS problems from app problems.

## 8. How to work on this project (owner's preferences and proven process)

Owner communication: short, fast messages with typos. Read for intent. The
owner wants autonomy and speed, dislikes being asked things that have an
obvious answer, but does want a confirmation before anything destructive or
production-facing unless they already said to deploy. When they say "push
and deploy", that is authorization to merge to `main` after verification.

Token budget: the owner asked to avoid screenshots (they are expensive).
Verify with `tsc`, `build`, `curl`/grep, and Playwright text/DOM
assertions via `browser_evaluate` or `browser_run_code_unsafe`, not images.
Playwright MCP can only upload files from inside the repo, so generate test
fixtures into `.playwright-mcp/testassets/` (gitignored). The built-in
browser pane cannot reach localhost.

Multi-agent pattern the owner asked for and that worked well:
1. A planner agent (the `Plan` type is read-only, so it returns the plan as
   text and the orchestrator writes it) produces `PLANNING_<feature>.md`
   with concrete UX decisions, architecture choice, motion spec, and a task
   split where each build agent owns non-overlapping files, plus a
   deploy-readiness checklist.
2. Build agents run in parallel in the background, each told which files
   they own and which they must not touch, each appending an
   `## Agent N report` to `BUILD_LOG_<feature>.md`.
3. The orchestrator does the integration pass: reads all reports, re-runs
   tsc/build, checks cross-agent contracts (class names, shared hooks,
   context placement). Integration bugs are common exactly at these seams;
   both real bugs in the last feature were found here.
4. Deploy per section 5, then verify live.

Verification bar for any UI change: `npx tsc --noEmit`, `npm run build`,
real Playwright flows including adversarial back/forward navigation and
rapid double-clicks, both themes, `prefers-reduced-motion` emulated, and
375px/768px widths.

Dev server: `npm run dev` on port 3000. Stale servers pile up; find the PID
with `netstat -ano | grep ":3000 " | grep LISTENING` and
`taskkill //PID <pid> //F` before restarting.
